# ◈ Siphon v1.1.1

**Quicker controls, a cleaner Upload tab, and downloads that finish instead of failing at the last step.**

</div>

---

This is a maintenance release on top of **v1.1.0**. Nothing about how you add or
browse sites has changed; your saved sites, queue, history and rclone setup carry
over as they are. If you are on v1.1.0, the app offers the update by itself.

## ✨ New

### Speed and parallel controls in the sidebar
The left sidebar now has a small card with the four settings you reach for most,
so you no longer have to open Settings or the Upload tab to change them:

| Row | Left | Right |
| :--- | :--- | :--- |
| ⬇ Download | speed limit | how many videos download at once |
| ☁ Upload | speed limit | how many files upload at once |

They are the same settings as before, not copies: change one in the sidebar and
the Settings / Upload tab follows, and the other way round.

### A tidier Upload tab
- The upload cards now look and behave like the download cards: same size, same
  state colours, same progress bar.
- **Filters** above the list — *All, Active, Queued, Failed, History, Paused* — with
  a short summary of the queue on the right. When a filter shows nothing, the
  list says so instead of staying blank.
- Buttons are grouped by what they do: **Add folder / Add files** on the left,
  and **Retry all / Cancel all / Clear cancelled / Clear finished** together on
  the right, so a "clear" is not one slip away from "add".
- Bigger, easier-to-hit buttons.

### A missing quality no longer fails the download
Some sites list a quality (say 1080p) that their video server no longer has, and
answer **HTTP 404** for it. Siphon used to ask for that file five times and give
up. Now it moves on to the next quality the page lists (720p, then 480p …) and
downloads that one. The log says so:
`the video server does not have this quality (HTTP 404); trying the next one the page lists.`
Only when *no* quality is left is the download marked failed — which means the
video really is gone from the site.

## 🐛 Fixed

- **"PermissionError" at the very end of a download (Windows).** While a
  download runs, its `.part` file is hidden so it does not clutter the folder.
  Windows refuses to rename or overwrite some hidden files, so a finished video
  could fail at the last step. The file is now made visible before it is
  renamed, and the rename is retried for a moment while antivirus or the Windows
  indexer still holds the file.
- **Progress kept if that last rename fails.** The resume bookkeeping is now
  removed only after the video has its final name, so a failed rename can be
  retried without downloading everything again.
- **A connection could read past the end of its piece.** When a free connection
  took over the far end of a slow piece, the original connection now stops
  exactly at the new boundary instead of reading on.
- **No more retrying a file that is not there.** A 404 from the video server is
  no longer retried five times on the same address (that only cost ~20 s per
  video).
